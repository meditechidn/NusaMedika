# AGENTS.md

Laravel 13 (PHP 8.3) SIMRS app ("MediTechV2") — an Indonesian hospital EMR. All code, commit messages, and UI text are in Indonesian; match that convention.

## Running everything through Docker

Stack: **Apache 2.4 + PHP 8.3 FPM (+ Redis opsional)**, database **PostgreSQL** (di luar Docker).

- No PHP is installed on the host **pada alur Docker** (semua PHP/artisan lewat container). All PHP/artisan commands must run in the app container:
  `docker compose exec app php artisan <cmd>`
  (Bila environment memakai **instalasi manual** — lihat `deploy/README-MANUAL.md` — PHP 8.5 terpasang di host dan `php artisan` bisa langsung dijalankan dari direktori project.)
- The compose file has **five services**:
  - `web` — Apache 2.4 (`mod_rewrite` + `mod_proxy_fcgi`), DocumentRoot `/var/www/html/public`, published **host 8081 → container 80** (`http://localhost:8081`). Request `.php` diteruskan ke `app:9000`.
  - `app` — PHP 8.3 FPM (image target `fpm`), menjalankan `composer install` lalu `php-fpm`; inilah container tempat `php artisan` dijalankan.
  - `redis` — **opsional** (compose **profile `redis`**), untuk cache/session/queue.
  - `queue` — `artisan queue:work redis`, juga ikut profile `redis`.
  - `vite` — Node 22 dev server, `network_mode: host` (port 5173).
- **Tidak ada service `db`.** Database = **PostgreSQL** yang jalan di host (di luar Docker); seluruh konfigurasi hanya di `.env`:
  `DB_CONNECTION=pgsql`, `DB_HOST=host.docker.internal` (dari container — compose memakai `extra_hosts: host.docker.internal:host-gateway`), `DB_PORT=5432`, `DB_DATABASE/DB_USERNAME/DB_PASSWORD`, `DB_SSLMODE=prefer`.
  Di host (instalasi manual) `DB_HOST=127.0.0.1`. Ganti server DB ⇒ ubah `.env` saja, lalu `docker compose up -d --force-recreate app web` + `config:clear`/`cache:clear`.
- Setup PostgreSQL (role `meditech`, db `meditech`, aturan pg_hba untuk jaringan Docker) dilakukan sekali lewat:
  `sudo bash deploy/setup-postgres.sh` (idempotent, aman diulang).
- **Redis opsional**: default `.env` memakai `CACHE_STORE=file`, `SESSION_DRIVER=file`, `QUEUE_CONNECTION=sync` (aplikasi jalan tanpa Redis). Untuk memakai Redis: `docker compose --profile redis up -d` + ubah `.env` ke `redis`/`redis`/`redis` dengan `REDIS_HOST=redis` (nama service, **bukan** `127.0.0.1`). Driver `database` untuk cache/session/queue **tidak boleh** dipakai — tabel `cache`/`sessions`/`jobs` tidak ada di migrasi project.
- The `Dockerfile` is multi-target: `base` (php:8.3-fpm + apache2 + composer), `fpm` (PHP-FPM + tuning), `apache` (vhost + `proxy_fcgi`). Ekstensi DB: `pgsql pdo_pgsql` (lihat section *PostgreSQL*). Ekstensi `redis` ikut terpasang (phpredis) walau Redis opsional.
- `.env` is gitignored but required. `.env.example` has placeholder DB values. Never commit `.env` (it contains the DB password). Backup konfigurasi lama disimpan di `.env.mysql-backup` (juga gitignored).
- The `.env` file is injected at container start (`env_file`) **dan** dibaca Laravel langsung dari file di volume, jadi setelah mengeditnya recreate container: `docker compose up -d --force-recreate app web` — otherwise the running app keeps the old values (e.g. a changed `OBJEK_*`/`JENIS_RAWAT_*` constant or DB setting is not picked up).
- **Jangan `php artisan config:cache`** — konstanta SIMRS dibaca via `env()` saat runtime.
- Vite runs in its own container; frontend assets load via `@vite` dev server (`public/hot`). Untuk production: `docker compose exec vite npm run build`.
- **Tampilan responsif (HP/tablet)**: aturan global, jangan di-hardcode per halaman — `layouts/app.blade.php` memakai sidebar **drawer off-canvas** di bawah 1024px (CSS `#sidebar-wrapper { transform: translateX(-100%) }` + class `is-open`; transisi **hanya** diaktifkan lewat class `sidebar-animate` supaya tidak ada animasi geser saat halaman dibuka — memakai utility `transition-transform` langsung akan membuat sidebar "melorot keluar" saat load). **Toggle buka/tutup sidebar**: tombol `#sidebar-toggle` di navbar (mobile → drawer, desktop → collapse ke mode ikon), tombol tutup `#sidebar-close` **di dalam header drawer** (wajib ada di mobile — navbar berada di balik drawer/backdrop sehingga tidak bisa dipakai menutup), tutup juga lewat backdrop / tombol Escape / klik menu. Drawer terbuka mengunci scroll konten lewat `style.overflowY` pada `#main-content` (bukan `body` — yang di-scroll adalah div konten) + class `body.drawer-open`. Status collapse desktop disimpan di `localStorage` key `nusamedika.sidebar.collapsed` dan **status `<details>` yang terbuka disimpan lalu dipulihkan** saat sidebar di-expand. `resources/css/app.css` punya blok `RESPONSIF MOBILE (global)`: grid berformulir jadi 1 kolom di bawah 640px memakai `:has(input, select, textarea)` (hanya grid standar, bukan `grid-cols-[...]`), baris tombol boleh membungkus, font input minimal 16px (anti zoom iOS). `resources/js/app.js` membungkus tiap tabel dengan `.nusa-table-scroll` (scroll horizontal) — jangan menggantinya dengan `overflow-x-auto` per view. `components/emr-split-layout.blade.php` menumpuk panel riwayat (45vh) di atas panel form di bawah 768px. **Saat menambah halaman baru, andalkan aturan global tersebut** — tidak perlu menulis ulang `sm:`/`md:` di tiap view.
- **Akses dari device lain via IP sudah otomatis** (jangan set `server.hmr.host` lagi): `vite.config.js` mendeteksi IP LAN (route default via UDP connect, fallback `os.networkInterfaces()`; override env `DEV_HOST`) lalu menimpanya ke `public/hot`, `server.host='0.0.0.0'`, `server.cors.origin=true`, `server.allowedHosts=true`, `server.origin=''` (URL aset **relatif** — kalau origin diisi, `laravel-vite-plugin` menulis URL absolut `http://0.0.0.0:5173/...` untuk webfont Font Awesome sehingga ikon sidebar hilang di device lain), dan `server.hmr.host` sengaja dikosongkan supaya client HMR memakai host dari URL `@vite/client`. `app/Support/Vite.php` (subclass `Illuminate\Foundation\Vite`, di-bind di `AppServiceProvider::register()`) override `hotAsset()` untuk mengganti host `public/hot` dengan **host request** — jadi asset & HMR selalu mengikuti IP/host yang diketik user. Jangan dikembalikan ke `hmr.host: 'localhost'` (asset jadi tidak termuat dari device lain).
- **Container `app` (dan `queue`) runs as the host user (`user: "1000:1000"`)** in `docker-compose.yml`, so any file written from inside the container (e.g. via `make:submenu`, `artisan`, caches) is owned by the host user (uid 1000) — editable/deletable from the host without `sudo`. Do **not** remove this `user:` line: without it the container runs as root and every created file becomes root-owned (hard to delete from the host). Note: if a teammate's host uid differs, they must adjust the value to their `id -u`/`id -g`. Container `web` (Apache) tetap root di dalam container agar bisa bind port 80 — file aplikasi tetap ditulis oleh container `app` (uid 1000).
- Gotcha: after adding `user: 1000:1000`, ensure `vendor/` and writable dirs (`storage/`, `bootstrap/cache/`) are owned by uid 1000 too — otherwise `composer install` at container start fails with "Permission denied" (fix with a one-off `docker run --rm -v "$PWD":/var/www/html -w /var/www/html --user root <image> chown -R 1000:1000 vendor storage bootstrap`).
- File konfigurasi container ada di `deploy/`: `deploy/apache/nusamedika-docker.conf` (vhost), `deploy/php/php.ini` (tuning PHP), `deploy/redis/redis.conf` (Redis), `deploy/setup-postgres.sh` (setup DB), `deploy/README.md` (panduan cepat).
- **Alternatif tanpa Docker** (host): `deploy/README-MANUAL.md` + `deploy/apache/nusamedika-manual.conf`, `deploy/php/php-fpm-pool-manual.conf`, `deploy/redis/redis-manual.conf`, `deploy/systemd/*` (queue worker & scheduler). Stack sama (Apache + PHP-FPM + Redis opsional), DB tetap PostgreSQL di luar Docker. Perbedaan penting: di host **`DB_HOST=127.0.0.1`** dan **`REDIS_HOST=127.0.0.1`** (bukan `redis`), dan `php artisan` bisa dijalankan langsung tanpa container.

## PostgreSQL (satu-satunya driver DB)

Aplikasi memakai **PostgreSQL**. Blok `mysql`/`mariadb` sudah dihapus dari `config/database.php` — jangan menambahkannya kembali. Aturan saat menulis query/migrasi:

- **`increments()`** → serial ✔ (satu-satunya bentuk yang dipakai).
- **JSON**: `$table->json(...)` ✔ (PG `json`, bukan `jsonb`).
- **Case-insensitive**: PostgreSQL `LIKE` bersifat **case-sensitive** (MySQL lama FREE dari collation). Karena itu **seluruh pencarian wajib pakai operator `ilike`** — sudah dikonversi di 59 call site. Jangan menulis `'like'` lagi.
- **Regex**: operator PG `~` (bukan `regexp`). Dipakai di `GenerateHelper::generateNoMr()`.
- **`GenerateHelper::resetSequence()`**: PG `setval(pg_get_serial_sequence(...), max+1)` — dipanggil di akhir `DatabaseSeeder` untuk 38 tabel.
- **Tidak ada `TIMESTAMPDIFF`**: selisih waktu dihitung `FLOOR(EXTRACT(EPOCH FROM (NOW() - r.tgl_masuk)))`; jumlah hari `CURRENT_DATE - DATE(r.tgl_masuk)`. Contoh lengkap ada di `ListPasienRanapController::ekspresiLos()`. Fungsi yang **ada** di PG: `NOW()`, `CONCAT()`, `LPAD()`, `MOD()`, `FLOOR()`, `COALESCE()`, `DATE()`.
- **View `header_ehr`** (`2026_08_28_000038`) memakai `CONCAT_WS('.', ...)` ✔ kompatibel PG.
- **Case-sensitive unique constraint**: berbeda dari MySQL lama (`utf8mb4_unicode_ci` yang mengabaikan besar-kecil). Dua nilai yang berbeda huruf besar/kecil kini dianggap berbeda → perhatikan saat input kode/kode_barang.
- **`migrate:fresh`** = drop semua tabel (data lama hilang) — untuk DB yang sudah berisi data pakai `migrate` biasa.

### Jebakan PG yang sudah pernah menimpa (penting!)

1. **`insertGetId()` WAJIB menyebut nama PK.** MySQL memakai `LAST_INSERT_ID()` (nama kolom tak masalah), sedangkan PG memakai `RETURNING "id"` → error `column "id" does not exist` kalau tabel punya PK custom. Selalu tulis `insertGetId([...], 'pasien_id')`.
2. **`lpad()` hanya menerima `text`.** `MOD()`/`FLOOR()` di PG menghasilkan `numeric` → `lpad(numeric, ...)` error `function lpad(numeric, integer, unknown) does not exist`. Pakai `TO_CHAR(CAST(... AS integer), 'FM00')`.
3. **Alias wajib pada ekspresi SELECT.** Tanpa `as los`, PG memberi nama kolom `?column?` sehingga `$row->los` undefined di view (tampilkan "-" tanpa error). MySQL lebih_longgar di sini.
4. **`where('x', 'like', …)` tidak ada padanan CI di PG** → selalu `ilike`.
5. **Fungsi yang TIDAK ada di PG**: `TIMESTAMPDIFF`, `DATE_SUB`, `DATE_ADD`, `IFNULL`, `GROUP_CONCAT`, `DATE_FORMAT`, `UNIX_TIMESTAMP`, `LAST_INSERT_ID`, `FIELD()`. Yang ada: `NOW()`, `CURRENT_DATE`, `CONCAT()`, `CONCAT_WS()`, `MOD()`, `FLOOR()`, `COALESCE()`, `DATE()`, `TO_CHAR()`, `EXTRACT(EPOCH FROM …)`, `~` (regex).
6. **`GROUP BY` + kolom tak聚集**: PG mengizinkan kolom yang *functionally dependent* pada PK yang di-group (MySQL lenient, PG juga) — tapi ekspresi volatil (`NOW()`) tetap harus masuk select.
7. **Kolom boolean**: default harus `'0'`/`'1'` (string) — `DEFAULT 0` untuk `boolean` ditolak PG.
8. **Harness E2E tidak boleh hardcode `registrasi_detail_id`.** Pakai `rdId()` dari `tools/lib_pay.php` (mengambil id terbaru) — id 12 hanya berlaku pada database lama.

## Schema conventions (59 model + 9 EMR tables + 1 view + 7 tabel sosial/notifikasi)

The original 295 migrations (generated via `kitloong/laravel-migrations-generator` from a legacy SQL dump) were **deleted and recreated from scratch**. Now there are **88 clean migrations** — one per table referenced by the 59 Models in `app/Models/` plus the 9 EMR tables used via `DB::table()` (`emr`, `emr_detail`, `form`, `objek`, `objek_form_control`, `dashboard_menu`, `dashboard_menu_sub`, `dashboard_menu_sub_extra`, `akses_ehr`) plus the `header_ehr` view, `bed` (tabel legacy tanpa Model, dipakai query filter `ListPasienRanapController` — lihat catatan di bawah), dua pivot inventory `barang_supplier` & `supplier_distributor` (tanpa Model, dipakai via `DB::table()` di `SupplierController`/`DistributorController` — lihat bagian **Mapping Supplier/Barang & Distributor/Supplier**), dan tabel penunjang medis `tindakan`/`tarif`/`order_laboratorium`/`order_laboratorium_detail`/`order_radiologi`/`order_radiologi_detail` (dipakai Master Tindakan & alur Order Lab/Rad — lihat bagian masing-masing). The 227 legacy non-model tables and all legacy views were dropped. Tabel notifikasi (`notifikasi` + `notifikasi_penerima`) ditambahkan belakangan — lihat bagian **Notifikasi**.

- **Auto-increment PKs**: every PK (`{table}_id`) uses `$table->increments(...)` (Postgres `serial`). **Jangan set PK secara manual** di controller/seeder — biarkan Eloquent/DB mengisinya via auto-increment. `GenerateHelper::getNextId()` sudah dihapus.
- **`GenerateHelper::resetSequence($table, $pk = null)`**: dipanggil di akhir `DatabaseSeeder` untuk menyetel ulang sequence mengikuti ID maksimal setelah seeder mengisi ID eksplisit (sefault PK = `{table}_id`). Ini penting agar insert baru lewat aplikasi (auto-increment) tidak bentrok dengan ID seeder.
- **`GenerateHelper::generateNoMr()`**: `MAX(no_mr)+1` over **all** `pasien` rows (no `status_batal` filter — the `unique_no_mr` constraint covers soft-deleted rows too), padded to 7 digits.
- **No Laravel timestamps**: tables use `input_time`/`mod_time` (timestamp(6)) + `input_user_id`/`mod_user_id`. All models set `public $timestamps = false`.
- **Soft delete via `status_batal`** (null = active, 1 = deleted), not `deleted_at`.
- **Semua query GET (index/dropdown/opsi/relasi) wajib memfilter `status_batal`**: record aktif hanya yang `status_batal IS NULL` **atau** `status_batal = 0`; selain itu (1, dst.) berarti batal/terhapus. Pakai pola `where(function ($q) { $q->whereNull('status_batal')->orWhere('status_batal', 0); })` (atau `->where('status_batal', '!=', 1)` yang setara) — **jangan hanya `whereNull`** (record seeder bisa ber-`status_batal=0`). Berlaku juga untuk `join`/`whereHas`/relasi, kecuali ada alasan eksplisit menyertakan record batal (mis. `generateNoMr()`).
- Model PKs are custom (`user_id`, `menu_id`, ...) and some use `$primaryKey`, `$fillable` — check the model before assuming column names. Semua model membiarkan `$incrementing` default `true` (PK auto-increment).
- Tabel legacy yang **tidak** punya Model **tidak** dibuatkan migration — halaman yang menyentuh tabel tersebut akan error sampai migration/schema-nya ditambahkan. Yang kini sudah punya Model: `bed` (juga `BedLog`, `PindahRuangan` untuk fitur Bed Management Rawat Inap) dan seluruh tabel inventory/penunjang. Yang tetap tanpa Model: pivot `barang_supplier` & `supplier_distributor` (akses via `DB::table()`).

## Migrations & view

- Semua migration bersih, pakai `Schema::create` + `$table->increments(...)`; yang sidah ada `with `header_ehr` dibuat via `DB::statement("CREATE OR REPLACE VIEW ...")`.
- `migrate` wraps each migration in a transaction (rolls back on failure), so a failed run leaves the DB clean.
- The database at the configured host (server **eksternal**) already holds the **real legacy data**. `migrate:fresh` akan **DROP semua tabel** (termasuk ~227 tabel legacy + semua view yang tidak punya migration) lalu recreate hanya 39 objek di atas — destruktif & irreversibel, pastikan dulu sebelum dijalankan. Selalu cek `docker compose exec app php artisan migrate:status` dulu.

All are idempotent and safe to re-run (modul/menu/sub_menu/users use `updateOrInsert` keyed on the PK; `user_akses` uses plain auto-increment now — `getNextId` is gone). `DatabaseSeeder` calls `GenerateHelper::resetSequence()` (38 tabel) di akhir untuk menyetel ulang sequence setelah seeder mengisi ID eksplisit, agar insert auto-increment berikutnya dari aplikasi tidak bentrok. Users are linked to a `pegawai` via `users.pegawai_id` and `users.nama_pegawai` is copied from the pegawai record (admin→1, perawat→2, dokter→3).

**`ModulMenuSubMenuSeeder.php` kini dihasilkan otomatis** oleh command `php artisan seeder:sync-master-menu` (`App\Console\Commands\SyncMasterMenuSeeder`) — membaca record **aktif** (`status_batal != 1 OR NULL`) dari tabel `modul`/`menu`/`sub_menu`, lalu menulis ulang file seeder dengan `updateOrInsert` + komentar pengelompokan per modul/menu. Jadi setelah membuat modul/menu/sub_menu baru lewat aplikasi (atau langsung di DB), jalankan command itu — jangan edit seeder manual. Jalankan ulang `db:seed` bila perlu; seeder idempotent, record yang di-mark `status_batal=1` otomatis tidak ikut di-seed.

## Pasien Dummy (seeder data uji)

`database/seeders/PasienDummySeeder.php` membuat **1 pasien dummy lengkap** (`PASIEN DUMMY UJI`, no. MR dari `GenerateHelper::generateNoMr()`, ktp marker `DUMMY0000000001`) beserta 2 baris `pasien_nasabah` (BPJS Kesehatan + Umum/Mandiri, `hak_kelas_id` = Kelas 2), lalu mendaftarkan pasien yang **sama** untuk tiga layanan **pada hari ini**:

| Layanan | `registrasi.jenis_rawat` | Bagian tujuan | Ciri khusus |
|---|---|---|---|
| Rawat Jalan | `env('JENIS_RAWAT_RJ','RJ')` | `POLI INTERNA` | `terima_dari='DALAM'`, `prioritas` = cara masuk, **+ `registrasi_urut`** (urutan antrian) |
| Rawat Inap | `env('JENIS_RAWAT_RI','RI')` | `RUANG PERAWATAN MAWAR` | `tgl_keluar` NULL, `check_in` terisi, **`bed.pasien_id_1` + `status_bed=1`** |
| IGD | `env('JENIS_RAWAT_IGD','IGD')` | `INSTALASI GAWAT DARURAT` | `prioritas` = triase (`Kuning`), `registrasi_detail.triase`/`cara_masuk`/`lokasi_rawat`, `terima_dari='LUAR'` |

Semua unit lookup **per NAMA bagian**, bukan id hardcode. `penanggung_rawat.rawat_user_id` diisi user `dokter` (`user_id` 3) karena ketiga list memfilter `rawat_user_id = auth()->id()`.

- **Gotcha: 3 list itu punya join wajib yang berbeda.** List Pasien Dokter & IGD `LEFT JOIN billing` (list Dokter juga `registrasi_urut` + `penanggung_rawat`); List Pasien Ranap `INNER JOIN bed AS bd ON r.pasien_id = bd.pasien_id_1` — **tanpa mengisi bed, pasien rawat inap tidak akan muncul** di halaman itu. `List Pasien Ranap` juga hanya menjalankan query bila ada `?filter=1` di URL.
- **Idempotent**: dikunci pada `pasien.ktp`; `bersihkanRegistrasiDummy()` soft-delete registrasi dummy sebelumnya (beserta detail, `registrasi_urut`, `penanggung_rawat`) dan mengosongkan bed sebelum membuat yang baru. Menjalankan berkali-kali tidak menambah bari.
- **Toleran terhadap drift skema**: `hanyaKolomExisting()` membuang key yang kolomnya tidak ada di tabel (DB lokal bisa masih punya `pasien.gol_darah` sementara migration kini `golongan_darah`), jadi seeder tidak hard-gagal.

## Scaffold `make:submenu`

Command `php artisan make:submenu {path} [--force]` (`App\Console\Commands\MakeSubmenu`, auto-discovered) membangkitkan **scaffold kosong** (template raw) untuk satu sub_menu baru. Bukan seeder/route — hanya menyiapkan file controller + view standar agar tinggal diisi:

```bash
docker compose exec app php artisan make:submenu Administrator/ManajemenMaster/Contoh --force
```

- **Argumen `{path}`** = path relatif `{Modul}/{Menu}/{SubMenu}` (PascalCase). Leaf folder = segmen terakhir; basename = snake_case leaf (contoh path `Administrator/ManajemenMaster/Contoh` → folder leaf `Contoh`, basename `contoh`, URI/route basis `contoh`). Wajib mengikuti kendala yang sama dengan section *Modular structure* (leaf unik, PascalCase kata-kata utuh, dst.).
- **`--force`** melewati konfirmasi "file sudah ada?" (skip prompt saat controller/view sudah ada).
- Yang dihasilkan (semua file punya komentar + template minimal, **bukan** logika):
  - Controller `app/Http/Controllers/{Path}/{Leaf}Controller.php` — method `index/create/store/edit/update/destroy` **kosong, hanya komentar struktur** (import minimal `Controller` + model `Request`); tidak ada method `clearSidebarCache`. View call-nya (komentar) memakai `'moduls.{PascalPath}.{basename}'`.
  - Views `resources/views/moduls/{PascalPath}/{basename}.blade.php` + `{basename}_create.blade.php` + `{basename}_edit.blade.php` — hanya `@extends('layouts.app')` + `@section('content')` + `<x-page-header title="..." subtitle="..." />` (komponen `resources/views/components/page-header.blade.php`); tidak ada markup lain.
- **Langkah berikutnya** (dicetak command + wajib dikerjakan manual): isi Model & validasi di controller, isi view, buat record sub_menu dengan `file_sub_menu='{path}/{basename}'` (misal `Administrator/ManajemenMaster/Contoh/contoh`), lalu `php artisan route:clear && cache:clear` agar route/sidebar auto dibangun dari tabel `sub_menu` (lihat *Auto-route sub_menu*).
- Route prefix: `admin.{basename}` bila path berawal `Administrator`, selain itu `{basename}`.

## Konvensi: jangan mengetik ulang kode berulang

Aturan praktis saat menulis fitur **baru** maupun **memodifikasi** yang ada:

- **Filter/pilihan yang sering dipakai → buat blade component** (`resources/views/components/`). Jangan salin- tempel markup filter di banyak blade. Contoh yang sudah ada: `x-select_poliklinik`, `x-select_dokter`, `x-select_pasien`, `x-select_ruang_perawatan`, `x-select_ajax`, `x-informasi-pasien` (komponen class-based opsional, mis. `app/View/Components/`). Kalau satu blok markup/jQuery diulang di ≥2 halaman, refactor jadi component.
- **Fungsi/logika yang dipanggil berulang → taruh di helper**, bukan di setiap controller. Utama: `App\Helpers\EmrHelper` (operasi EMR), `App\Helpers\GenerateHelper` (no_mr, resetSequence), `App\Helpers\SelectOption` (opsi dropdown statis), `App\Helpers\AksesEhr` (gate akses EMR). Polanya: method statis tanpa state, dipanggil lintas controller/view.
- **Opsi dropdown tidak harus disimpan di database.** Pilihan statis/baru yang sifatnya enumerasi (status, kategori, jenis, dst.) cukup ditambahkan ke `App\Helpers\SelectOption::all()` lalu dipakai via `get()`/`render()` — tabel baru hanya diperlukan bila piliannya butuh data CRUD dinamis (poliklinik, dokter, kelas, nasabah, barang, dst.).

## Modular structure (semua modul)

The same modular layout applies to **every** modul, menu, and sub_menu in the sidebar:

- **Controllers**: `app/Http/Controllers/{Modul}/{Menu}/{SubMenu}/{SubMenu}Controller.php` — folder = StudlyCase of the modul name, the menu name, then the sub-menu. Folder leaf **harus PascalCase kata-kata utuh tanpa akronim** (misal `DaftarGawatDarurat`, `ListPasienRanap`, `NasabahPasien`) karena controller & path view diturunkan dari nama leaf tersebut. **Leaf = identitas unik sub_menu**: nama folder (segmen kedua terakhir dari `file_sub_menu`) **wajib unik di seluruh app** — URI = basename blade file (lihat di bawah), jadi dua sub_menu dengan leaf sama akan bentrok. Leaf harus NamaBenda + kata pembeda (misal `ListPasienDokter`, `ListPasienRanap`, `ListPasienGawatDarurat` berbagi kata dasar "Pasien" tapi leaf beda); JANGAN pakai nama menu/modul saja sebagai leaf dan JANGAN buat dua sub_menu dengan leaf sama (kalau memang halaman sama, gabung jadi satu sub_menu). Examples: `Registrasi/Pendaftaran/DaftarRajal/DaftarRajalController.php`, `Registrasi/Pasien/DaftarPasien/DaftarPasienController.php`, `EMR/EmrDashboard/EmrDashboardController.php`, `Administrator/ManajemenUser/User/UserController.php`.
- **Views**: `resources/views/moduls/{modul}/{menu}/{sub_menu}/{basename}*.blade.php` — **path folder harus IDENTIK persis dengan path controller** (nama segmen & huruf besar/kecil sama, misal `file_sub_menu='Registrasi/Pasien/DaftarPasien/daftar_pasien'` → folder view `resources/views/moduls/Registrasi/Pasien/DaftarPasien/` **dan** controller `App\Http\Controllers\Registrasi\Pasien\DaftarPasien\`). Karena `derive()` memakai `file_sub_menu` yang sama untuk membentuk namespace controller dan path view, kalau keduanya berbeda maka salah satunya tidak ditemukan (class not found / view 404). **Nama file blade = basename (snake_case of folder leaf) + sufiks halaman**: halaman utama `{basename}.blade.php` (misal `daftar_pasien.blade.php`), form tambah `{basename}_create.blade.php`, form ubah `{basename}_edit.blade.php`, form gabungan `{basename}_form.blade.php` (contoh `wilayah_form.blade.php`). Panggil view via `view('moduls.{PascalPath}.{basename}[_suffix]')` (titik, bukan slash), contoh `view('moduls.Registrasi.Pasien.DaftarPasien.daftar_pasien')`. Sub-folder partial EMR tetap di `moduls/EMR/PartialForm/`.
- **`sub_menu.file_sub_menu`** sekarang menyimpan **path view lengkap BESERTA nama file blade (tanpa ekstensi)**, misal `Registrasi/Pasien/DaftarPasien/daftar_pasien`. Segmen terakhir (basename) = nama file blade = **URI & basis nama route**; folder di depannya dipakai untuk namespace controller dan path view (folder = path base view PascalCase, misal `Registrasi/Pasien/DaftarPasien`, `Administrator/ManajemenMaster/Bagian`). Dari nilai inilah URI, nama route, controller, dan URL sidebar **diturunkan otomatis** (lihat section *Auto-route sub_menu*). Gunakan `'#'` hanya untuk sub-menu yang butuh id dinamis (EMR forms).

## Auto-route sub_menu (route & CRUD diturunkan dari tabel `sub_menu`)

Semua route non-EMR (Registrasi, Rawat Jalan/Inap/GD, seluruh Administrator) **tidak lagi ditulis manual di `routes/web.php`**. Routes dibangkitkan otomatis dari tabel `sub_menu` lewat `App\Providers\SubMenuRouteServiceProvider` (metode statis `derive()` + `url()` yang kini juga menggantikan `App\Support\SubMenuRouter` — kelas tersebut sudah dihapus, tidak ada lagi tabel OVERRIDES):

- **Penamaan normal & bebas override**: karena semua folder leaf sudah dinormalisasi menjadi PascalCase kata-kata utuh tanpa akronim (lihat section *Modular structure*), derivasi murni struktural — **tidak ada tabel OVERRIDES per `sub_menu_id`**. `derive()` membaca **basename blade file** (segmen terakhir `file_sub_menu`), jadi URI **identik dengan nama file blade** — ini memudahkan debugging (URL `daftar_pasien` = file `daftar_pasien.blade.php`). Aturan: `uri` = basename (misal `file_sub_menu='Registrasi/Pasien/DaftarPasien/daftar_pasien'` → URI `daftar_pasien`); `controller` = `App\Http\Controllers\{folder}\{folderLeaf}Controller` (folder sebelum basename, harus sama persis dengan `file_sub_menu`). **Gotcha basename**: nama folder/class harus full-word (bukan akronim) karena basename ditulis manual di seeder sebagai snake_case folder leaf — `DaftarIGD` → `daftar_i_g_d`, makanya folder IGD dieja penuh (misal sub-menu "Registrasi IGD" → leaf `DaftarGawatDarurat`, "List Pasien IGD" → leaf `ListPasienGawatDarurat`). Basename wajib unik di seluruh app (URI/route bentrok bila sama).
  - `param` route = basename (mengikuti konvensi `Route::resource`, agar panggilan `route('...', ['wilayah' => $id])` yang memakai key model tetap cocok).
  - `route_name` = `admin.{uri}` bila folder berawal `Administrator`, selain itu `{uri}` (misal `admin.bagian.index`, `daftar_pasien.store`). **Nama route HARUS dipertahankan** karena semua blade/controller memanggil `route('admin.bagian.index')`, `route('daftar_pasien.create')`, dst.
- `SubMenuRouteServiceProvider` (`bootstrap/providers.php`) — di `$this->app->booted()` (sehabis web.php dimuat, jadi route eksplisit di web.php selalu menang), untuk tiap `sub_menu` aktif (status_batal != 1) yang `file_sub_menu`-nya bukan `'#'`:
  - Bila controller hasil `derive()` **ada** (`class_exists`), daftarkan route **CRUD sesuai method yang benar-benar ada** di controller (index/create/store/edit/update/destroy; hanya method yang `method_exists`), semua bermiddleware `web`+`auth` (wajib — tanpa `web` session/auth tidak terbangun). Contoh: `DaftarRajalController` hanya punya `index`+`store` → hanya 2 route.
  - Bila controller tidak ada (view statis/landing), daftarkan `Route::get('/{uri}', SubMenuViewController::class)` untuk path-view-nya (bila view `moduls.{path}` — yaitu `moduls.{folder}.{basename}` — ada).

**Konsekuensi penting (`routes/web.php`):** hanya route auth (`/login`), `logout`, `/dashboard`, EMR (dashboard_pasien, `emr/form/...`, soap, pengkajian), dan API yang ditulis manual. Route Registrasi/Administrator/Rawat*.jangan ditulis manual — nanti bentrok/duplikat dengan yang auto (provider menolak URI yang sudah `$existing`, sehingga route baru yang auto tidak terpasang).

**Route non-CRUD / reusable tetap ditulis manual di `routes/web.php`:** auto-router hanya mengurus CRUD per-sub_menu (`index/create/store/edit/update/destroy`). Route yang **bukan** bagian dari CRUD sebuah halaman — mis. aksi ajaib `POST /registrasi/{id}/batal`, endpoint ajax/Select2, export/import, cetak, endpoint utility lintas modul — didaftarkan manual agar reusable dan tidak terikat pola sub_menu. Karena provider menolak URI yang sudah `$existing`, route manual yang URI-nya lebih dulu terdaftar selalu menang atas route auto yang bentrok. **Karena itu route manual berbentuk `/x/{param}` WAJIB diberi `->whereNumber('param')`** — tanpa itu ia akan menangkap path milik auto-route (mis. `GET /forum/{topik}` mencuri `forum/create`, lalu `show()` dipanggil dengan id `"create"` → 404).

**Sidebar:** link sub-menu tidak lagi `url(file_sub_menu)` (itu akan menunjuk ke `/Registrasi/Pasien/DaftarPasien` yang tidak ada), melainkan `\App\Providers\SubMenuRouteServiceProvider::url($file_sub_menu)` (`resources/views/layouts/sidebar.blade.php` ~line 63).

**Cache:** route dibangun per-request (tak perlu `route:cache` untuk dev; tiap request ke Apache → PHP-FPM membangun route anew). `SubMenuController` memanggil `SubMenuRouteServiceProvider::flushPathCache()` (bersamaan dengan clear sidebar cache) saat sub_menu berubah. `php artisan route:cache` didukung (route memakai controller), setelah snapshot path baru perlu `route:cache` ulang; `route:clear` saat kembali ke dev.

## Master wilayah (provinsi/kabupaten/kecamatan/kelurahan)

- Empat tabel `provinsi`/`kabupaten`/`kecamatan`/`kelurahan` **tidak punya kolom audit** (`input_time`/`mod_time`/`input_user_id`/`mod_user_id`) — hanya PK, parent id, `nama_*`, `status_batal smallint`, `kode_wilayah_*`. Jangan set kolom audit di seeder/controller. Model-nya (`App\Models\{Provinsi,Kabupaten,Kecamatan,Kelurahan}`) punya scope `aktif()` (`status_batal != 1 OR null`) dan relasi berantai (`provinsi→kabupaten→kecamatan→kelurahan`).
- CRUD wilayah di `Administrator\ManajemenMaster\Wilayah\WilayahController` memakai satu route resource `/wilayah` + query `?tab=provinsi|kabupaten|kecamatan|kelurahan` (form/index dibedakan per tab). Simpan record via pola `new Model; assign; save()` — `Model::create()` gagal karena PK tidak ada di `$fillable` (kolom PK NOT NULL → "Not null violation"). Soft-delete cascade (hapus provinsi → semua kabupaten/kecamatan/kelurahan di bawahnya, dst.) wajib pakai `whereIn('col', $ids->all())`, bukan `where('col', $collection)` (Query Builder menganggap Collection sebagai scalar → `Invalid parameter number`).
- API Select2 untuk cascade: `api.wilayah.{provinsi,kabupaten,kecamatan,kelurahan}` di `ApiWilayahController`, balikan `{results:[{id,text}]}`, difilter parent lewat `provinsi_id`/`kabupaten_id`/`kecamatan_id`, urut nama, hanya `aktif()`.
- Form pasien (tambah/edit) menyimpan hanya `kelurahan_id`; blok `.wilayah-cascade` berisi 4 `<select data-wilayah="..." data-url="...">` yang dimuat berjenjang dari `resources/js/select.js` (`initWilayahCascade`). Prefill edit dikirim dari controller sebagai variabel `$prefill` lalu dirender `data-prefill='@json($prefill)'` — **jangan** tulis array literal multi-elemen langsung di argumen `@json([...])`: `compileJson` memecah argumen dengan `explode(',')` sehingga array terpotong dan menghasilkan ParseError.

## Zona waktu: app vs server database (PENTING)

- `config/app.php` → `timezone = Asia/Makassar` (UTC+8), tetapi **server database eksternal bisa berjalan di UTC**. Selisihnya **8 jam**.
- Semua timestamp harus ditulis dari PHP (`now()`, `Carbon::now()`), **jangan** pakai `NOW()`/`NOW(6)` MySQL di seed/insert manual — hasilnya 8 jam di masa lalu dan langsung dianggap kedaluwarsa oleh perbandingan `where('tanggal_kadaraluarsa','>', now())` (scope `StatusSosial::belumKedaluwarsa()`).

## Pengkajian Risiko Jatuh (EMR, berbasis usia)

Rancangan lengkap + referensi ilmiah: `docs/PENGKAJIAN_RISIKO_JATUH.md`. Pusat logika: `app/Helpers/RisikoJatuhHelper.php`.

- **Instrumen dipilih otomatis dari usia pasien** (`instrumenUntukUsia()`): anak `< 14` → **Humpty Dumpty** (`HDS`), dewasa `14–59` → **Morse Fall Scale** (`MFS`), lanjut usia `>= 60` → **Timed "Up and Go"** (`TUG`). **Sydney Scoring** (`SYDNEY`, STRATIFY modifikasi) tersedia sebagai alternatif semua usia dan bisa dipilih manual lewat dropdown.
- **Skor & tingkat risiko dihitung di server** (`RisikoJatuhHelper::hitung()`) — input tersembunyi dari frontend **diabaikan** lalu dihitung ulang dari jawaban mentah, jadi angka tersimpan tidak bisa dimanipulasi dari browser. `deteksiInstrumen()` jadi fallback bila field `risiko_jatuh_instrumen` tidak ikut terkirim (form dirender ulang / integrasi lama).
- **Variabel yang disimpan** (form 3 & 4, objek 89–113): `risiko_jatuh_instrumen`, `risiko_jatuh_skor`, `risiko_jatuh_label`, `risiko_jatuh_intervensi`, `risiko_jatuh_ringkasan`, plus jawaban tiap item (`hds_1..7`, `mfs_1..6`, `syd_*`, `tug_detik`).
- **BUG — skor tidak berubah saat radio diganti**: jangan menyimpan hanya radio **pertama** sebuah grup (`querySelectorAll(...)[0]`) lalu membacanya lewat `.checked` — memilih opsi kedua membuat radio pertama ter-uncheck sehingga jawaban terbaca kosong dan skor tidak bergerak (hanya opsi pertama yang terbaca). Simpan **seluruh grup** (`item.els = Array.prototype.slice.call(panel.querySelectorAll('[name="X"]'))`) lalu cari elemen yang `checked` (`nilaiItem()`). `gcs_jumlah` (readonly) dihitung otomatis `gcs_e + gcs_v + gcs_m` — jangan menulis atribut `value` dua kali pada satu input.
- **Gotcha TUG**: kategori TUG dibandingkan dengan batas atas 95% CI norma usia (**nilai mentah**, mis. 10,2 dtk untuk 70–79 — bukan hasil `ceil()` 11, yang akan salah classifying 11 dtk). Normalisasi hanya untuk tampilan. `>= 30` detik = risiko tinggi. Norma: Bohannon 2006 meta-analisis.
- **Partial**: `pengkajian_risiko_jatuh` (panel utama + JS hitung live) & `_risiko_jatuh_instrumen` (tabel item per instrumen). Partial `pengkajian_up_go` lama **dihapus** (3 parameter, tidak membedakan usia, tanpa skor). `layouts.iframe` **tidak** merender `@stack('scripts')` → JS partial harus `<script>` inline.
- **BUG PENTING — `$emr_data` harus dibaca per-variabel**: `EmrDataWrapper` hanya mengimplementasikan `ArrayAccess` dan `__toString()` mengembalikan string kosong. Semua partial lama menulis `value="{{ $emr_data ?? '' }}"` (scalar) sehingga **setiap field menampilkan nilai yang sama dan tidak ada radio/checkbox yang tercentang**. Pola benar: `{{ $emr_data['agama'] ?? '' }}` dan `{{ ($emr_data['nyeri'] ?? '') === 'ya' ? 'checked' : '' }}`. Sudah diperbaiki di 6 partial. Radio `_radio` (`*_radio`) adalah kontrol bantu di luar mapping `emr_detail` — statusnya diturunkan dari field teksnya, **jangan** simpan.
- **`pasien.tgl_lahir` sekarang `date`** (bukan `timestamp(6)`) — migration `2026_10_01_000006`. Column `TIMESTAMP` di MySQL hanya menerima 1970–2038, sehingga pasien lahir sebelum 1970 (justru kelompok usia TUG) gagal disimpan dengan `ERROR 1292 Incorrect datetime value`.

## EmrHelper (pusat operasi EMR)

`App\Helpers\EmrHelper` menggantikan **semua** pemakaian `env('FORM_ID_*')` dan `env('OBJEK_ID_*')` di controller & blade. Semua method statis:

- **Form lookup**: `formBySlug($slug)`, `formById($id)`, `formIdBySlug($slug)`, `forms()`.
- **Objek & mapping**: `objeks()`, `objekMap($formId)` → array {objek_form_control_id, form_id, objek_id, variabel, nama_objek}, `objekVariabels($formId)` → daftar variabel string, `objekId($formId, $variabel)` → objek_id (nullable), `objekIdsByVariabels($formId, $variabels[])` → array unik objek_id untuk query `whereIn`.
- **Baca EMR**: `emrList($formId, $registrasiId, $perPage=5)` (paginate + nama pegawai), `emrById($emrId)`, `emrDetailByVariabel($emrId)` → array `['variabel' => value]` (kompatibel data lama objek_id NULL), `emrDetailByObjek($emrId)` → array `[objek_id => value]`, `latestEmr($formId, $registrasiDetailId)`, `latestValuesByVariabel($formId, $registrasiDetailId, $variabels[])`.
- **Tulis EMR**: `insert($formId, $data[], $registrasiDetailId)` → simpan `emr` + `emr_detail` (hanya variabel yang ada di mapping, objek_id dari mapping, otomatis transaksi), `update($emrId, $formId, $data[])` → soft-delete detail lama + re-insert, `delete($emrId)` → soft-delete emr + detail.
- **Utilitas**: `backfillObjekId($formId)` → isi `objek_id` NULL pada `emr_detail` lama sesuai mapping variabel (idempotent).

**Pola migrasi controller lama**:
```php
// Sebelum (env)
$form_id = env('FORM_ID_SOAP');
$details[env('OBJEK_ID_SUBJECTIVE')]

// Sesudah (EmrHelper)
$form_id = EmrHelper::formIdBySlug('soap');
$details = EmrHelper::emrDetailByVariabel($emr_id); // keyed by variabel
$details['subjective']
```

- **`$historyGrouped` = riwayat KUNJUNGAN, bukan riwayat emr.** Komponen `x-emr-split-layout` memakai bentuk `[ 'Y-m-d' => [ 'Nama Bagian' => registrasi_detail_id ] ]` untuk dropdown "History" (judul = `Carbon::parse($date)`, tautan = `$getLink($registrasi_detail_id)`). Sumbernya `registrasi_detail` seluruh kunjungan pasien — **jangan** menyusunnya dari baris `emr`. Riwayat emr per form sudah otomatis diambil sendiri oleh `x-emr-history-table` (memakai `EmrHelper::getHistoryForForm()`). Pencarian duplikat sudah dipusatkan di `EmrHelper::historyKunjunganGrouped($registrasi_detail)` — pakai helper itu, jangan tulis query sendiri.
- **Partial blade EMR** (`moduls/EMR/PartialForm/*.blade.php`): pola `$emr_data[env('OBJEK_ID_X')]['variabel']` diganti ke `$emr_data['variabel']` (flat keyed by variabel). - **SOAP / Pengkajian Awal / Pengkajian Harian**: ketiganya punya controller & view sendiri (`PengkajianAwalKeperawatanController` → `moduls.EMR.PengkajianAwalKeperawatan.index`, `PengkajianHarianKeperawatanController` → `...PengkajianHarianKeperawatan.index`, dideteksi otomatis oleh `DynamicFormController` lewat nama folder) dan memakai `EmrHelper`; gate akses via `AksesEhr::can($formId, 'read|create|update|delete')`.
